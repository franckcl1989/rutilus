## 诚实未竟项

1. **settle 的 bounded-scan 残余**：`settle_duplicate_offers` 用 `list_pending(request.site_id, CENTER_DISPATCH_OFFER_SCAN_LIMIT)`（上限 256）——同 id 并发行若落在截断窗口外（≥256 pending 行的病理队列）不可见，残留双 pending 行。同 id 无双执行（站点按 §17.5 id 去重），且与既有 retry scan 的可见性口径一致（dispatch.rs:79-84 已有「bound is not a hard cap on the scan's visibility」文档，fall-through directed 读兜底），如实登记。
2. **跨站点并发对的残余**：并发 enqueue 落在他站队列（判定与 enqueue 之间端点恰被 re-home）时，addressed-site pending scan 不可见——同 id 两行分属两站。由 re-home 模型（旧站吊销使旧站无法执行）兜底，与核验员对 W9-C-2 降 LOW 的论证同源；settle 文档（:842-847）已注明。
3. **web 层 503 贯通断言未加**：应用层全链已钉（dispatch → `Err(CenterDispatchError::Outbox(_))`）；HTTP 503 状态断言需要 web harness（app crate，含 center_runtime.rs 的 Store→503 映射），超出本区文件白名单（仅 dispatch.rs + center_outbox_repository.rs + 登记文件），留待 web 区 agent 或主 agent 决策。
4. **并发工作区**：本区执行期间共享工作区存在其他区 agent 在途改动（migration/docs/ui/app 等 21 个文件，git diff 可见），本区只动 `application/src/center/dispatch.rs` 与 `docs/r9-findings/A1.md`；最终全量测试与 clippy 均在含其在途改动的共享工作区通过，未遇编译中断。
