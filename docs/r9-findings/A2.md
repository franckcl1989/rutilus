## 诚实未竟项

1. **执行期受阻与复跑**：W9-C-1 Center 测试调试期间曾并行改动多个文件（临时探针与最终形态之间多次往返），`cargo test -p rutilus --lib` 全量复跑一次耗时约数分钟，最终代码态已复跑全绿（数量与 W8 区基线一致，见门禁）。`cargo clippy` 在最终快照上运行；并行 agent 在途改动若造成编译受阻，以最终快照为准。
2. **doctor 制品文件存在性检查（方向②）未做**：医生自检是只读面（`migration_counts` 式只读打开），查「Ready 行 ↔ 文件」需要制品行查询；`SqliteStore::open` 会迁移且非只读，不可用于运行中实例；对运行中 db 做整文件副本会因 WAL 撕裂不可靠。该缺口由 ①（restore 从源头拒绝毒包）与 ③（运行时每连接带修复指引的显式分类 warn）覆盖——毒状态在 restore 时被拒、或在同步引擎的 warn 中被指名——doctor 增量收益低，登记为已知权衡。
3. **W9-C-1 Center 测试的注入面**：console 优雅 drain 的注入通过真实 HTTP 登录 handler + derivation gate 钩子（`hold_derivation_gate_for_test`，cfg(test)）实现——handler 的密码验证在闸上等待，与 Argon2id 实际耗时无关，时序确定性不依赖机器速度。该测试依赖 web 登录 handler 的 unknown-user 路径（dummy 验证 + started/failed 审计对）；若该路径后续改动，测试需同步。Edge 侧用 mock server 注入，无此依赖。
4. **W9-S-3 流式分发的 mid-stream 错误形状**：整文件读旧实现任何读错误都发生在任何入队之前；流式实现下，中途读错误（非首块）会留下 manifest + 部分块的 outbox 集合（与旧实现中途 outbox 失败留下的部分集合同形），重连重发由中心侧幂等吸收——首块先于 manifest 的次序保住了「缺文件零入队」这一关键性质，其余为既有语义。
5. **停机时长上限**：新序最坏 ≈ 后台 join + 10s console drain + 2s final drain（旧 ≈ 10s 并行 + 2s）；有界且不显著变长，`GRACEFUL_DRAIN_TIMEOUT` 与 final drain 预算嵌套关系已消除（final drain 不再与 console drain 并行）。
