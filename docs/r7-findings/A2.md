## 诚实未竟项

1. **W7-C-1 的完整接线未跑集成**：`run_center_connection` 需要真实 mTLS `AcceptedCenterConnection`，无法在单元测试里端到端驱动；测试覆盖自检 helper 与「撤销先提交 → 竞态者注册 → 自断」的完整时序，接线本身由编译与评审保证。复查读失败按 fail-closed 关闭连接，属新增行为（原有行为是继续在线）。
2. **W7-C-3 的停机 final drain 分支以空队列验证**：`the_center_runtime_retries_queued_audit_appends` 的断言发生在停机之前（证明周期 drain spawn 接线），停机 final drain 走空队列路径；其重试行为本身与 standalone 侧共享同一函数。如需验证「停机前最后 30s 内入队的事件被最终排空」，需第二次 5s 写锁注入，成本收益不划算，未做。
3. **touch 仍按 site 键**：陈旧连接被后继会话取代后、在退出前的极短窗口内（一个 select 迭代）若收到帧，`touch` 会更新新会话的 liveness 戳——仅影响 `list_online` 排序的观感，无正确性影响；flush 探针已使该窗口微秒级。未额外加代际校验（避免为观感问题扩大 diff）。
4. **W7-E-8 探针粒度**：每 pending 条目一次 std Mutex 锁（flush_limit=64 上限内可忽略）；一个已在飞的 send 仍会完成投递（帧间检查，符合「在发送前或每帧间检查」的修复要求）。
5. **W7-F-7a 的测试依赖 tokio Mutex FIFO**：撤销任务先入队先取得闸门，顺序确定性由 current-thread runtime + spawn/yield 次序保证；若调度异常导致 dispatch 先取得，测试会响亮失败（断言不匹配）而非静默通过。
