## 诚实未竟项

1. **W10-C-1 无测试覆盖**：自败分支在 axum 0.8.9 下不可达（serve 恒返回 Ok），本区按定案不加测试——若未来依赖升级引入可失败的 serve 路径，该分支的行为（含本次次序对齐）将由升级时的测试补齐，现无自动化钉扎。如实登记。
2. **W10-F-2 的 re-settle 只覆盖 retry scan 的两个 Resolved 出口**：`resolve_candidate` 的 Resolved 还有 TTL 过期路径（其重投走 `deliver_retry`，settle 已内置）与在飞路径（本区已覆盖）——scan 外无其他返回 Resolved 的出口；「恰一次额外扫描」的成本按每次 resolved retry 计入（有界、与既有扫描同量级），若未来 retry 频率成为热点可再评估在 settle 内提前短路，现登记。
3. **W10-E-5 注入点的 mock 语义边界**：`enqueues` 计数与注入触发是 mock 专属行为，对生产 `list_pending` 语义零影响（生产无此字段）；触发条件「enqueues > 0」依赖测试流形的确定性（本测试流恰一次 enqueue），若未来该流形新增 enqueue 路径，注入点可能提前触发——测试注释已说明确定性前提，如实登记。
4. **并发工作区**：本区执行期间共享工作区存在其他区 agent 在途改动（ci.yml / 两个 docs 文件等），本区只动 `app/src/standalone_runtime.rs`、`app/src/center_runtime.rs`、`application/src/center/dispatch.rs` 与 `docs/r10-findings/A2.md`；门禁全量测试在含其在途改动的共享工作区通过。
