## 方案选型与诚实评估（任务书指定必答项）

1. **Failed 终态为何未实现（核心偏差，如实登记）**：任务方案②「持久失败制品置 Failed 终态」经全链核实**机械不可行**——(a) domain 生命周期 `Artifact::mark_failed` 经 `require_uploading` 拒绝一切终态行（`Ready` 视为终态、「a finished verdict is never overwritten」，domain/src/artifact.rs:458-469）；(b) persistence `SqliteStore::update_artifact` 对终态行一律 `TerminalConflict`（persistence/src/artifact_repository.rs:317-322），即使用引擎的既有 `update_artifact` 边界把 Ready 行写为 Failed 也会在生产路径报错。(c) 本区文件白名单（仅 center_sync.rs）不允许新增 trait 方法或改仓库侧。**替代语义**：行保持 Ready（诚实——该行确实曾通过 finalize 校验；制品列表仍可见），失败以每 120s 一次的 `tracing::error!`（带修复路径）暴露，游标永不越过坏制品，**永不放弃**（W9-S-2 的「跳过即不一致」论证对 Failed 行适用的问答题：若 Failed 可行，跳过+游标推进是安全的（列表可见、操作者可补救）；现因 Failed 不可行，任何跳过形式都退回 W9-S-2 拒绝的静默不一致，故选择「停在该制品 + 每轮重试」）。额外收益：W9-S-2 修复路径「re-restore 文件」在重试语义下自动愈合（Failed 语义下必须 delete+re-upload）。成本：坏制品之后的 Ready 制品在该制品修复前持续等待（与 W9-S-2 接受的旧语义一致，但通道存活、诊断明确、outbox 有界）。
2. **瞬态/持久区分**：NotFound → 持久（ArtifactFileMissing，吸收）；EOF 字节数不一致 → 持久（ArtifactSizeMismatch，吸收）；其他 IO 错误 → 可能瞬态（ArtifactRead，传播 + 重试，半套已回滚）。分类函数既有分支保持，新增 SizeMismatch 独立分支。
3. **游标语义**：持久失败后游标不推进（停在失败前的最后一个成功制品）；Failed 行不可达故「after_anchor 过滤天然跳过」的机制不存在——重试由游标停留保证。已登记于上表 D-1 行。
4. **中心侧 Uploading 行残留（S-3）**：站点放弃/暂缓制品的两种形态都可能给中心留下 Uploading 行——(i) 截断在旧代码下已推送的半套（本次修复前已发生的历史状态，修复后不再产生新半套）；(ii) 先周期 flush 中途断线曾送达的半套在回滚时被本地退休、不再补发。两者均为有界残留（每制品至多一行），由中心侧既有幂等吸收与操作者处置；**S-3 由主 agent 登记**。

## 诚实未竟项

1. **Failed 终态未实现**（见方案选型 1）：需要 persistence 侧新过渡（如 `Ready→Failed` 专用方法 + domain 生命周期放开）+ trait 扩展 + 全部 mock 同步，超出本区白名单。当前替代语义（重试 + 每周期 error 日志 + 行保持 Ready）已覆盖 D-1/D-2/E-2 的可达目标；若主 agent 决定推进 Failed 语义，建议登记为 S-区/持久层区的新任务。
2. **坏制品之后的 Ready 制品等待其修复**：吸收 + 停在失败点使后续制品每周期重试队列靠后（不会饿死——修复后全部按序分发，测试已钉），但修复前持续不达中心。与 W9-S-2 接受的旧语义一致；Failed 语义（若可行）可消除此等待。
3. **bounded-scan 残余**：retire 扫描界 = 单制品全集的字节上限（2049 @1MiB）；前置 pending 超过此界的病理队列（多制品×大文件交错 + 其他流积压）中该制品条目不可见，残留待下轮失败时再扫（W9-C-2 settle 先例同款口径）。
4. **锚点回归盲区**（沿用 W9-S-2 未竟项）：游标已越过某制品后其文件再丢失（手动删文件/部分恢复）→ after_anchor 过滤天然跳过、不重查。restore 侧一致性检查（W9-S-2 ①）从源头拒绝该毒状态；本区未扩展运行时侧锚点扫描（成本不成比例），如实登记。
5. **中心侧 Uploading 残留**：见方案选型 4，S-3 由主 agent 登记；本区测试未覆盖中心侧收件（center 侧 harness 在其他文件）。
6. **日志断言未加**：吸收路径的 `tracing::error!` 未用日志捕获断言（本文件无既有日志捕获测试模式）；通过返回语义 + 游标/outbox 状态断言间接钉住。
