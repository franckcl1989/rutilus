## R6-D-4 登记的限制（补偿队列）

已知限制（基线即存在，本轮仅登记，未消除）：

- **补偿队列纯内存**：`AUDIT_COMPENSATION` 为进程级 `OnceLock<Mutex<VecDeque>>`，无持久化 outbox。crash 或停机时仍在队列中未重试成功的事件**丢失**——语义是"进程存活期内尽力重试"，不是持久保证（`standalone_runtime.rs:89-97` 原注释即承认；R6-C-3 把停机丢失从"整队丢弃"缩小到"预算内尽力排空 + 剩余 warn"）。
- **256 上限丢最旧**：`AUDIT_COMPENSATION_EVENTS = 256`，满队新入队驱逐最旧条目（R6-5 起 warn+计数，但事件本身仍丢）。高失败率下最旧事件可能永远得不到重试。
- **drain 间隔**：`AUDIT_COMPENSATION_DRAIN_INTERVAL = 30s`，一次 tick 批量排空至多 8 次连续失败（R6-C-7）；瞬时故障期间重试延迟最大约 30s+8 次尝试耗时。
- **幂等前提**：R6-C-4 幂等分支以"事件 id 唯一且 trail 末事件 id 相同即视为已落盘"为契约；若调用方以同一 id 携带**不同内容**重发，会静默视为已应用（调用方缺陷，非存储可判定）。

## E-11 查询接口（A2 定稿，供 A6 对接）

**接口签名（web crate 边界，`web/src/lib.rs:154` 起，offset 方法在 `:167`）：**

```rust
pub trait AuditEventQuery: Send + Sync {
    type Error: Error + Send + Sync + 'static;

    fn list_recent_events(&self, limit: NonZeroU64)
        -> BoundaryFuture<'_, Result<Vec<AuditEvent>, Self::Error>>;

    // E-11 新增（必选方法，无默认实现；blanket `&Query` 转发）
    fn list_recent_events_with_offset(&self, limit: NonZeroU64, offset: u64)
        -> BoundaryFuture<'_, Result<Vec<AuditEvent>, Self::Error>>;
}
```

**行为契约（StandaloneState 实现，`app/src/standalone_runtime.rs:532-562`）：**

- `offset == 0`：完全等同 `list_recent_events(limit)`——读预热内存尾（AUDIT_TAIL_EVENTS=1024，oldest→newest，查询倒序取最新）；尾锁毒化时回退 store（V5A-6 warn 路径不变）。
- `offset > 0`：直接读 store 有界列表 `list_recent_audit_events(limit, offset)`（persistence 签名新增 `offset` 参数，`persistence/src/audit_repository.rs:130-152`，sea-orm `.offset(offset)` 后按 OccurredAt/EventSequence 双列倒序）；不经过内存尾，故尾缓存淘汰不隐藏分页历史。
- **fail-closed**：`AUDIT_TAIL_WARM_FAILED` 置位（启动预热发现损坏行）或 store 读失败 → 返回 `Err(StandaloneAuditTailError)`（HTTP 层映射 503），**绝不返回空列表伪装"历史已尽"**。
- **响应结构不变**：仍是 `Vec<AuditEvent>` 最新在前，无分页信封；web 测试 mock 全部补齐该必选方法（9 个 web/tests 集成 mock + web 内部 `UnavailableWriteServices`；write_path/capability_path 的 state mock 实现真实 skip(offset) 语义）。
- A6 接法：handler 中 `state.services.list_recent_events_with_offset(limit, offset)`（`Services: AuditEventQuery`），解析 `offset` 查询参数（建议 0 起点、非负、上限约束沿用 AUDIT_QUERY_MAX_LIMIT 风格）。
