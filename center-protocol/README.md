# rutilus-center-protocol

The Rutilus site-to-center wire protocol (design §8, §15). The crate carries
exactly four things:

* the Protobuf messages of §15.2 plus `NegotiationResult` (the fifteenth
  message added by the 0.7.0 design pass), generated by `prost-build` from
  `proto/rutilus/center/v1/center.proto` and re-exported at the crate root;
* the version-negotiation pure functions (`negotiate`,
  `capability_ledger_hash`);
* the frame codec (`encode_frame`/`decode_frame`) that bounds every
  envelope with `MAX_FRAME_BYTES` on both sides of the wire;
* the protocol constants (`CENTER_PROTOCOL_VERSION`, frame and heartbeat
  limits, the pinned `NV_REDFISH_BASELINE`).

The generated wire types are not wrapped: the wire type is the wire type
(design §7.2). The crate depends only on `rutilus-domain` (for the stable
capability codes the ledger hash is built from), `prost`, and `sha2`; it
never touches `axum`, `tokio`, `SeaORM`, or `nv-redfish`.

## Layout

```
proto/rutilus/center/v1/center.proto   # the wire contract
build.rs                               # prost-build + protoc-bin-vendored (bundled protoc)
src/framing.rs                         # length-prefixed frame codec + bounds
src/generated.rs                       # prost-generated types (nested include!)
src/negotiation.rs                     # version negotiation pure functions
src/lib.rs                             # constants + re-exports
```

## Build prerequisites

The build script runs the `protoc` binary that `protoc-bin-vendored` ships
inside the crate (no system `protoc`, CMake, or C++ toolchain is required,
design §8). The bundled binary is a Google-built release for the build
host's platform, so every environment builds the same way.

## Testing

```
cargo test -p rutilus-center-protocol   # 15-message round trips, frame bounds, negotiate matrix, pinned constants
cargo clippy -p rutilus-center-protocol --all-targets
cargo fmt --check -p rutilus-center-protocol
```
